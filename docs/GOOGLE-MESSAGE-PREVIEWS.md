# Optional Google message-text previews

Google is the only email/calendar provider in the current scope. Inbox header reads keep the `gmail.metadata` permission by default. Body previews require the separately selected `gmail.readonly` scope and a browser reconnect. A separate device-local body-approval flag defaults off for older configurations and is set only by the selected body-access reconnect. Disconnect/configuration replacement clears it. The local scope allowlist is restricted to the scopes selected in this app, even if Google reports an older broader grant. Google documents the distinction in [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes) and [message formats](https://developers.google.com/workspace/gmail/api/reference/rest/v1/Format).

After authorization, each body request requires the read-consent control and a selected-message action. The app requests [messages.get](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/get) with `format=full`. It prefers inline text/plain, otherwise converts HTML to inert text, removing script/style/embedded content. Images and remote resources are not loaded. Separate attachment requests, account mutations, mail sends and automatic AI context access are absent. A full MIME response may itself contain inline attachment data, which is not opened or saved by this viewer.

Current limits: 4 MiB provider JSON response, 200 MIME parts, depth 12, 1 MiB combined decoded text, 20,000 HTML markup boundaries, and 12,000 UTF-8 bytes in the returned preview. Truncation is labelled. Non-UTF-8 encodings use replacement characters; this is a bounded text preview, not a complete MIME mail client. Data stays temporary unless the owner explicitly saves a copy into the encrypted vault.

Synthetic tests cover scope separation, plain-text preference, attachment exclusion, inert HTML and Unicode-safe truncation. Live acceptance needs owner Google OAuth client configuration and account sign-in; no real Google messages were accessed during implementation. Background account aggregation remains a separate gap.

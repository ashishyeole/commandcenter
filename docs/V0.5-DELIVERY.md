## Documents and tasks

SQLite migration 5 stores ordinary attachment originals (up to 10 MiB each, 1,000 versions) with SHA-256, owner, version parent and trash timestamp. The library searches names and up to 100 KB of extracted UTF-8 text. Binary files are indexed by filename; supported raster originals and text have inert previews. Markdown preview does not execute HTML. Sensitive documents still belong in the encrypted vault. Ordinary attachments are plaintext in SQLite and readable exports.

Portable schema 4 includes attachment metadata and original archive files, validates checksums and preserves transactional imports. The pre-existing 64 MiB archive expansion limit remains. Dependency selection can include linked records and task prerequisites outside the initially selected categories only when opted in. Ordinary peer sync now transfers attachments with separate attachment and owner-category pairing scopes; see ATTACHMENT-SYNC.md.

Recurrence now supports selected weekdays, an inclusive end date and a prerequisite task. Completing a prerequisite activates its waiting dependants; recurring parents trigger dependants when their final occurrence completes. Desktop polling and mobile snapshots activate completed dependencies received from another device. This is not a general external-event rules engine.

## Research, AI and model controls

arXiv and RSS/Atom collection uses bounded XML parsing, no external entities, pinned public HTTPS destinations, no redirects, cached results and provider cooldowns. Feed claims are identified as publisher statements. The app does not independently verify paper quality or factual claims.

Cloud AI is opt-in, using a user-configured OpenAI model and OS-protected API key. The user reviews the exact selected-context payload and approves each request; a payload hash prevents approval from being reused after context changes. Attachments and vault contents are excluded. `store: false` is requested; this is not a zero-retention guarantee. Citation-ID membership is checked, not factual entailment. Incomplete responses are marked for review. Cancelling locally cannot undo already transmitted provider work.

Local Ollama operations inspect model metadata/license and running memory, pull/update with progress, and delete only after typing the model name. Installation/model requests are not performed during development. Runtime cancellation may leave partial files or provider-side work. Hardware fit is not invented from incomplete metadata.

## Google account connections

User-supplied Google Desktop OAuth client configuration; system-browser consent; temporary loopback callback; random state and PKCE S256; OS-protected credentials and refresh tokens. Separate metadata-only Gmail and read-only Calendar scopes. Inbox reads fetch at most 20 sets of subject/from/date headers per page; calendar reads return primary-calendar events in a 30-day UTC window with pagination. No mail sending, mark-read, event writes, automatic fetching or AI access is exposed.

Results are transient in Settings and the unified Inbox. Inbox views clear on hide or after five minutes. An explicit action can unlock the local vault and save an encrypted snapshot. Disconnect disables local access and removes credentials; a separate button also requests provider revocation. Provider setup, consent-screen restrictions, credentials and live account acceptance remain user/environment steps. Reset clears local enablement; it does not claim to revoke remote grants.

Client sampling, roots, elicitation and other server-originated requests are rejected. Container network/mount restrictions remain unchanged; tools needing host/IDE/network permissions require separately approved integrations. Image dependencies are not downloaded automatically. No container or MCP server was actually launched in this pass.

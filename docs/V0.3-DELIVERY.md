# v0.3 — local workflows, scheduling and mobile discovery

This increment adds functioning source paths to the existing application. Compile/package results are recorded in ACCEPTANCE.md. Runtime, security and acceptance tests remain intentionally unrun at the user's request. Full PRD completion is not claimed.

## Desktop workflows

- **Today:** configurable widgets for capture, local overview, pins, next tasks, upcoming dates, cached discoveries and latest automated results. Settings also holds local discovery interests and periodic backup reminders.
- **Workspaces → Plans, comparisons & connections:** editable record-based proposal, PRD, curriculum, robotics experiment, farm-research and poker-study templates; Markdown export; atomic creation of linked notes and task plans; side-by-side record comparison; incoming/outgoing relationship browsing. Templates preserve missing information as placeholders and do not fabricate research or imply contact with anyone.
- **Assistant:** persistent conversations, last-six-turn context, selected current records, current local date, source-ID membership checks and clear limitations. Membership checks do not validate whether a source supports a claim.
- **Automations:** opt-in public-source refresh and local Ollama brief recipes. Each recipe has explicit saved permissions, specific record IDs, interval, status, last/next attempt, failure log, retry delay and manual run. Editing scope revokes UI approval until re-approved. Scheduling runs only while the application is open. Missed intervals do not replay a backlog. AI cancellation remains available.
- **Discover:** persistent read/unread/dismissed states, duplicate-URL collapse, local interest-match sorting, idempotent save of a URL, and observed GitHub star differences between matching query snapshots at least one minute apart. The normalized daily rate is a sampled average, not a forecast or independently verified trend.
- **Tasks:** custom every-N-days/weeks/months recurrence, reminder snooze and optional hourly escalation of unresolved critical tasks outside quiet hours. Deadlines are preserved by snoozing; repeats remain date-based and advance one occurrence on completion.
- **Projects:** explicit per-project, per-device periodic Git observation (up to eight repositories, every two minutes), unchanged-snapshot suppression and opening the previously authorized folder. This is polling, not a filesystem watcher; no IDE/model inference or source-tree upload is performed.
- **Vault:** manually entered multi-entity, multi-account finance/bankroll register; integer-cent amounts; distinct currencies; monthly category budgets; income/expense/net summaries; statement-review flags. These are private encrypted records, not provider balances, double-entry accounting, bank reconciliation or payments. Reconciled means the user checked the entry.

## Backup and portability

Archive schema 3 adds validated non-permission preferences and feed caches to full-scope exports. Schema 1/2 remain readable by the new app. Older app versions should reject schema 3. Selective exports exclude global preferences and caches. Restore must explicitly opt in to missing configuration/caches; existing local values are kept. No notification authorization, automation recipes, project paths, keys or provider credentials are transferred.

**Data & privacy → Scheduled encrypted backups** is a separate opt-in feature. A native folder picker grants the destination; local and OS-mounted NAS/cloud folders are supported. Direct cloud/WebDAV provider adapters are not implemented. The user's recovery password is held in OS secure storage for unattended jobs; users must keep a separate recovery copy. Changing that password changes new archives only.

Vault inclusion has an additional saved permission: it authorizes background use of the OS vault key solely for encrypted backup, including when the interactive vault is locked. Enabling it requires an unlocked vault. Unchecking/revoking the scope stops future scheduled vault reads after saving. Interactive vault lock does not revoke a previously approved backup permission; this is displayed in the UI.

Every backup is encrypted, written atomically, read back, decrypted and structurally/checksum validated before success metadata is recorded. No plaintext intermediate archive file is written. Retention is off by default. When authorized, rotation only considers this app's recorded files in the exact chosen folder and checks their saved ciphertext hash before deleting them. User-modified files and unrelated files are retained. Reset does not remove prior backup files or OS credentials.

## Native mobile

Both mobile sources support explicitly approved public GitHub and Hacker News search, bounded HTTPS responses, no redirects, SQLite feed cache and saving a discovery into the local library. Both understand desktop custom recurrence strings in manual exchanges. Mobile feeds do not imply project sync, remote approvals, a mobile vault or background continuous execution.

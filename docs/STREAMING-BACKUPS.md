# Large encrypted streaming backups

Data & privacy offers `.paccs` backups alongside the existing ZIP/PACC01 format. PCCSTR01 processes individual records rather than collecting the full archive in RAM. Current bounds: 8 GiB encrypted file, one million data/config frames, 24 MiB plaintext per frame and existing per-attachment 10 MiB limits. The identity set used for duplicate checking grows with record count; payload buffers are bounded per frame. Large imports hold the database transaction/lock and can be cancelled.

Includes notes/tasks/saved records, structured workspaces and their explicit links, original attachments, full ordinary timeline history, safe display preferences, public feed caches and research collection definitions. Optional private records require an unlocked source vault and are sealed with the receiving device’s key on import. Device keys, secure-store integration credentials, folder grants, account connections, OS schedules, sync trust/cursors and other permissions are excluded. Ordinary record text and URLs are retained as entered; the exporter does not classify or redact secrets embedded in free-form content. This is a desktop format; mobile companions retain their existing exchange and vault backup formats.

## Format and integrity

- Header: eight ASCII bytes `PCCSTR01`, 16 random salt bytes, four random nonce-prefix bytes.
- Password key: 32 bytes from Argon2id v19 with fixed memory 19,456 KiB, two iterations, one lane and a 32-byte output (matching current standard-backup defaults). New exports require at least 12 Unicode code points.
- Each frame: unsigned big-endian 32-bit ciphertext length followed by AES-256-GCM ciphertext and tag. Nonce is the four-byte archive prefix followed by the unsigned big-endian 64-bit frame index. The full 28-byte header is authenticated as additional data.
- Plaintext is UTF-8 JSON with adjacent `kind` and `value` fields. Recognized kinds: Item, Record, Attachment, History, Feed, Preferences, Collections, Vault, End. Unknown versions/kinds/fields are rejected.
- The final encrypted End frame contains the count and SHA-256 digest of the concatenated exact plaintext bytes of preceding frames. Truncation, altered ordering/content, a missing footer or trailing bytes fail verification.
- Native preview makes an encrypted temporary copy of the selected file. Its SHA-256 is bound to the review. Import recomputes the encrypted-file digest while reading and checks it before committing. Temporary plaintext archive files are never created.

## Restore policy

Preview verifies every frame, schema/value validation and the terminal manifest before presenting counts. New record IDs are imported in one SQLite transaction; existing IDs keep the local record, including conflicts. Existing configuration is retained. A wrong password, invalid frame, missing owner, corrupt footer, changed review checksum or cancellation before commit rolls the transaction back. The optional linked-copy policy imports every incoming current record under a fresh ID, with an imported-copy title. It remaps explicit workspace links/owners, task prerequisites, attachment owners/version chains and matching history payloads. History event IDs are also fresh. Local records and all local configuration are retained. External references keep their original IDs; history whose entity has no current incoming record is omitted. Deleted records remain deleted. Each deliberate copy import creates another set of copies; missing-only import remains idempotent.

Linked-copy mode makes two authenticated passes and keeps an ID map proportional to the number of entities. The second pass must match the first pass and the reviewed encrypted-file checksum before committing. Vault copies receive fresh IDs and are sealed with the receiving key. The mode selector resets for each newly selected archive, and changing the policy clears approval. Per-record selection and field-level merging are not offered for large streams.

Export uses a consistent database read transaction, writes an encrypted temporary file beside the destination, verifies it, then publishes it atomically. Reset epochs prevent stale previews/exports from being published into the new profile state. Background source or cloud jobs are not restored by importing a backup.

## Verification

Repository tests cover an actual file larger than 64 MiB, import idempotence/local conflict preservation, attachments/links, receiver-key vault encryption, linked-copy relationships/history/attachment versions, unchanged originals/configuration, UTF-8 title bounds, changes between copy passes, permission exclusion, corrupt/truncated/trailing data, wrong password/review digest, authenticated duplicate IDs, unsupported format versions and interrupted reads. Native QA has verified streaming export, wrong-password rejection, preview and missing-only duplicate import using synthetic records. Linked-copy UI coverage is recorded separately in `testing/`.

This is a new application format with documented bounds, not a claim of independent cryptographic review or unlimited library size. Known standard formats remain supported; future formats fail explicitly until a compatible migration is implemented.

Scheduled encrypted backups now offer streaming .paccs for approved local or mounted folders, including mounted NAS/cloud drives. Existing schedules default to standard .pacc; switching formats clears approval and disables the schedule until saved again. Archives are flushed, synced and fully verified before atomic publication, and retention hashes files in bounded chunks. The app must be open; no after-quit streaming backup job is installed. Actual secure-store-backed unattended schedule execution has not received native UI acceptance. Direct HTTPS WebDAV retains the standard archive size limit. Per-record selection/field-level merging and direct WebDAV streaming remain future work.

## Selected fields and WebDAV continuation

Desktop preview now offers a third restore policy: choose up to 1,000 ordinary items/workspace records and select incoming mutable fields. Review pages contain 20 records. Each selection binds to a current-record SHA-256 and the full archive checksum. Identity, recurrence and existing relationships stay local; unselected fields/records are skipped. Missing ordinary records can be selected whole. This policy excludes attachments, vault records, timeline/configuration and feed caches; use missing-only or linked copies for those. The final authenticated stream applies in one SQLite transaction, rejects stale review and rolls back on integrity failure.

Approved WebDAV schedules can now use PCCSTR01 directly. The writer stages ciphertext to disk, verifies the authenticated manifest, then uploads 64 KiB chunks with a fixed length and no-clobber condition. It downloads the entire remote file in bounded chunks and compares the ciphertext SHA-256 before recording success. Retention applies only to owned files with matching full hashes and strong ETags using conditional deletion. Missing ETags keep old files with warnings. Cancellation/reset can leave remote encrypted partial/orphan files; they are not silently marked verified. Recovery downloads only an owned inventory file under the current approved destination into an atomic local ciphertext file; open it through the password/manifest preview before restoring. Real WebDAV authentication and server conditional-write behavior still require owner/provider acceptance. Nothing was uploaded to a real destination during this pass.

# Release preparation — 0.5.0

Source preparation is available; no production release is signed, notarized, uploaded or published. Current artifacts are development builds. Runtime acceptance remains unrun at the user's request. Production signing and store acceptance cannot be inferred from compilation.

## Desktop

Unsigned development builds use the normal Tauri config. A separately selected `apps/desktop/src-tauri/tauri.release.conf.json` enables updater artifacts. Set `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` in a secure release environment, then run the normal Tauri release build with `--config src-tauri/tauri.release.conf.json`. The updater signing key is distinct from Apple/Windows code-signing credentials. Never commit keys or store them in this repository. The app requires explicit trust of an HTTPS publisher URL and its public key before checking/installing updates.

macOS production distribution requires the owner's Developer ID identity and notarization credentials; configure the Tauri Apple signing environment in the release system. Windows requires the owner's code-signing certificate or signing service configuration. Build each architecture on its appropriate runner. The existing manually triggered package workflow creates unsigned development artifacts, not a production release.

After signed platform builds, `scripts/prepare-update-manifest.py` prepares an **unpublished** update manifest and SHA-256 inventory from explicitly selected artifacts and their `.sig` files. It refuses duplicate platforms, missing signatures and existing output files. Example arguments: `--version 0.5.0 --base-url https://YOUR-PUBLISHER/releases/0.5.0 --artifact 'darwin-aarch64=/absolute/path/Personal Command Center.app.tar.gz' --notes-file docs/V0.5-DELIVERY.md --output /absolute/path/latest.json`. Supply only real publisher URLs when preparing a release. The script checks inputs, not cryptographic signature validity; release review must verify signatures against the trusted public key, code signing, artifact contents and intended version. Uploading/publishing is a separate explicitly authorized action.

The NSIS uninstall hook offers an interactive Cancel path to return to Data & privacy for a verified backup/reset before removal. It never deletes user data or keys. Silent/update removal does not show the prompt. OS-controlled macOS/mobile deletion cannot be intercepted. Intentional data deletion must use the application's reviewed reset flow while the app is installed. The Windows hook has not been compiled on a Windows runner.

## Native mobile

iOS source uses the owner's Xcode team and provisioning profile for device archives. Current outputs target Simulator and are not App Store submissions. Create a distribution archive with an explicitly selected team, profile, application identifier and export options in the owner's release environment. Android source currently builds ARM64 debug APKs. Release signing configuration below reads environment variables only; no keystore is generated by the app or committed. Set `PCC_ANDROID_KEYSTORE`, `PCC_ANDROID_KEY_ALIAS`, `PCC_ANDROID_STORE_PASSWORD`, `PCC_ANDROID_KEY_PASSWORD`; run Gradle `:app:bundleRelease` only after placing the current ARM64 Rust library in the JNI directory using `scripts/build-mobile-core.sh android`. Missing signing variables leave the artifact unsigned; never distribute it as a signed release.

## Store materials and unresolved owner decisions

Proposed title: Personal Command Center. Short description: Private notes, tasks, projects and research, with optional connected services. Description: A local-first personal workspace for capturing ideas, planning work, reviewing saved research and continuing across explicitly paired devices. No mandatory account or proprietary cloud service. Optional integrations require setup and consent. Private vault records are encrypted at rest. Encrypted backups need a separately retained recovery password.

Before submission supply the legal publisher name, support URL/contact, hosted privacy-policy URL, final application identifiers, screenshots from actual release builds, audience/content ratings, export-compliance answers and platform-specific privacy disclosures. These cannot be truthfully invented. Review provider data handling against the exact enabled features. Do not claim that connected providers collect no data, that encryption replaces device security, or that finance/travel/event information is independently verified. No paid plan, subscription product or billing processor is configured.
